## Conflicts identified

**None found in content.** `ITM15_MASTER_BUILD_RUNBOOK.md`, `docs/PRODUCT_GUIDE.md`, and `docs/WALLY.md` are internally consistent — they were evidently authored as one coherent set (same upload commits, cross-referencing paths and phase numbers exactly).

**The Storyline/Experience Build Bible reinforces, rather than resolves, the already-flagged Wally spec-vs-art conflict.** It independently specifies day-by-day Wally costumes in more detail than `docs/WALLY.md` §20 did — explorer/archivist (Day 1), traveller with passport/backpack (Day 2), historian/camera (Day 3), "People Champion" (Day 4), futuristic Builder (Day 5), Connector (Day 6), Future Wally (Day 7). Two independent controlling documents now specify this system; the actual `MASCOTTE.zip` art still has zero costume variants. This makes it more certain this is a real, doubly-specified product requirement — not something to quietly drop — and correspondingly more important to resolve with the product owner (new art, or an explicit scope decision) before Phase 13 Wally work starts.

**Recurring pattern, third occurrence — flagging directly rather than silently re-fixing again.** Duplicate re-uploads of controlling docs keep landing on `main` via the GitHub web UI, outside any session: `67f425b`'s relocation was undone once at repo root (`3860a23`, fixed in `632f720`), then `docs/Walumo_ITM15_Wally_Product_Build_Guide.md` reappeared a third time — this time correctly inside `docs/`, but under the pre-relocation filename, still byte-identical to `docs/PRODUCT_GUIDE.md` (confirmed with `diff`, removed). Whatever process is doing these uploads (a saved browser session, a script, a habit of re-attaching the original file when editing something else in the GitHub UI) is worth identifying — the fixes take one commit each, but a fourth occurrence should get a direct question to the user rather than another silent removal.

**New, unresolved — needs the product owner, not a repo fix.** `docs/WALLY.md` §3.1/§20 (explorer/traveller character, Day 1-7 costume changes) conflicts with the actual production mascot art the user supplied (`MASCOTTE.zip`, 2026-09-13): a single consistent Walumo-branded professional character with no costume variation, built around a punctuality/clock theme rather than an ITM-history-explorer theme. Not resolved by this repo — see `docs/PROJECT_STATE.md` and the header comment in `src/wally/rendering/assets.ts`. Flag to the product owner before Phase 13 work begins.

**Resolved twice now — watch for a recurrence.** The structural conflict between the documents' path assumptions and the actual repository layout was fixed by relocating them into `docs/` (commit `67f425b`). A subsequent commit (`3860a23`, "Add files via upload," landed directly on GitHub via the web UI, outside this session) re-added byte-identical copies of `WALLY.md` and the Product Guide `.md`/`.docx` at repo root — confirmed identical with `diff` before removing them again (commit after `cb639c9`). If this happens a third time, it's worth asking whoever/whatever is doing the web-UI upload to stop targeting repo root, since it silently recreates the exact path-authority conflict the runbook warns about.
