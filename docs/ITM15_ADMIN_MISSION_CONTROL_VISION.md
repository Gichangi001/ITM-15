# ITM@15 — Admin Mission Control: "Live Game Studio" Vision

**Status:** Aspirational vision document, pasted directly into a Claude Code session by the product owner. Not yet part of the phase plan in `docs/PRODUCT_GUIDE.md` or `ITM15_MASTER_BUILD_RUNBOOK.md`, and not a controlling spec on its own — see the authority note below.

**Authority level:** 5 (supporting source material), same tier as a Word document per the runbook's authority model (`ITM15_MASTER_BUILD_RUNBOOK.md` §1.1). It does not supersede `docs/PRODUCT_GUIDE.md`'s phase list or `docs/WALLY.md`'s Wally contract. Where it conflicts or overlaps with either (see below), those remain controlling until the product owner explicitly updates them.

**Why this file exists:** the document describes dozens of genuinely new systems — a visual Challenge Builder with an IF/THEN rule engine, a no-code Game Builder, original race mechanics (Fork/Alliance/Switch/Gate/Express Pass/Rewind/Boost/Lock), a full Easter Egg Engine, a Golden Ticket economy with transferable powers, Secret Missions, undercover "Wally Agents," live Bounties, a Twist Engine, Comeback mechanics, a Daily Boss Mission with a shared Africa-lighting-up visualization, streaks, an Achievement Builder with rarity tiers, Wally-Token auctions, Mystery Boxes, risk/reward and wager challenges, community polls that change gameplay, a drag-and-drop Story Scheduler with live override, a dedicated Wally Live director, a Theme Director, a Photo Wall director, an Emergency Pause, a fairness-focused audit log, an Engagement Radar, a Game Health Score, Player/Squad/Country 360 views, a pre-publish Game Simulator, a Test Player Mode, a Draft→Preview→Test→Scheduled→Live→Ended→Archived content pipeline, a Game Template Library, an AI-assisted (human-approved) Game Master, a Difficulty Engine, and a one-click "Surprise Me" event generator.

None of this is small. Each numbered section in the source document is realistically its own build phase (schema + RLS + server actions + admin UI + player-facing UI + tests + security review), several considerably larger than any single phase already in `docs/PRODUCT_GUIDE.md` §26. Building it in one pass would violate this project's own non-negotiables — "smallest complete vertical slice," every feature slice ending in a real quality/security gate, and (per this very document's own §55) "every button must connect to real state," never a decorative control. So this file captures the vision faithfully, without attempting to build it in one sitting, and without silently expanding `docs/PRODUCT_GUIDE.md`'s scope on its own authority.

## Where this maps onto the existing phase plan

Some of this document's sections describe **the same underlying capability** already itemized in `docs/PRODUCT_GUIDE.md`, just with richer creative direction:

- §1 (Admin Home / live KPIs + activity feed), §2 (Game Director quick-action panel), §54 (Mission Control mockup) → **already exists**, see `src/app/admin/page.tsx`. The document's own emoji-prefixed live-feed style and "everything important can happen from here" panel are a legitimate design upgrade to apply to the real dashboard already built — see the changelog entry in `docs/PROJECT_STATE.md` for what was actually adopted from this.
- §3-§6 (Challenge Builder, challenge types, conditions, a visual IF/THEN rule engine) → overlaps with Product Guide §9 (Content Engine) and §18.1-§18.2 (Question/Mission editor), Phase 6. The rule engine specifically is new scope beyond what Phase 6 currently implements (a plain admin form) — a real addition, not yet built.
- §10-§12 (Easter Egg Engine) → new scope. No equivalent anywhere in `docs/PRODUCT_GUIDE.md`.
- §13-§17 (Golden Ticket system, transferable powers) → **distinct from** `docs/WALLY.md` §23's "Golden Wally" (a single rare, server-authoritative discovery event with a claim/verification flow already specified there). Golden Tickets as described here — an inventory of multiple, stackable, sometimes-transferable power-ups — is new scope and should not be conflated with Golden Wally when it's eventually built (Phase 6's/WALLY.md's Golden Wally spec is more tightly scoped and already has server-authority rules written down; Golden Tickets would need the same rigor before being built).
- §18 (Golden Wally) → already specified in `docs/WALLY.md` §23, Phase 13+ (Wally). This document's description is compatible with, not a replacement for, the existing spec.
- §19-§21 (Secret Missions, Wally Agents, Bounties) → new scope, no equivalent.
- §22-§25 (Twist Engine, Comeback mechanics, Daily Boss Mission, Streaks) → the Boss Mission's "light up Africa as each country completes" idea is a strong, concrete visualization for Product Guide's existing country-vs-country Unity Points mechanic (§10, §14) — worth prioritizing over the more speculative sections if/when this vision is scoped into real phases.
- §26-§27 (Achievement Builder, rarity) → overlaps with Product Guide §17 (Achievements/passport), Phase 17. Rarity tiers and an admin-facing builder (vs. hardcoded achievement rules) are real additions beyond that phase's current scope.
- §28-§31 (Auctions, Mystery Boxes, risk/reward, wagers) → new scope, uses a "Wally Token" currency not defined anywhere else in the product's economy — would need its own design pass (what mints tokens, what they're worth, whether real prizes are ever involved) before being buildable safely.
- §32 (polls that change gameplay) → extends Product Guide §11 (Voting), Phase 9, which currently only supports informational/recognition polls.
- §33-§34 (Story Scheduler, live override) → extends Product Guide §17.2 ("Upcoming Scheduled Events") and the `scheduled_events` table already in the DB model (§23) — real, buildable extension of existing scope.
- §35 (Wally Director) → **already specified** in `docs/WALLY.md` §16 ("Admin Mission Control — Wally Control Room"), Phase 13. This document's mockup is compatible creative direction for that phase, not new scope.
- §36 (Theme Director) → already specified in Product Guide §19, Phase 15.
- §37 (Photo Wall Director) → extends the already-built moderation queue (`/admin/submissions`) and gallery (`/gallery`) — "Feature Live" as a distinct admin action beyond plain approve/reject is a real, small, buildable addition to Phase 10's existing code.
- §38 (Emergency Pause) → already specified in Product Guide §17.3 ("Pause Game") and the runbook's incident-response section (§33) — not yet built.
- §39-§40 (Audit Log, Game Fairness) → **already built and enforced**, see `docs/PROJECT_STATE.md`'s Phase 6-10 write-up — every admin action in this project writes an audited `score_events`/`audit_logs` row with a required reason for manual point changes, exactly as this document describes.
- §41-§46 (Activity Map, Engagement Radar, Game Health Score, Player/Squad/Country 360) → overlaps with Product Guide §22 (Analytics), Phase 19, and §17.1's dashboard header metrics. Squad-specific views need squad assignment to exist first (currently a disclosed, unbuilt gap — see `docs/PROJECT_STATE.md`'s Phase 6-9 write-up).
- §47-§49 (Game Simulator, Test Player Mode, Draft→Live pipeline) → new scope. The existing content engine already has a DRAFT→LIVE status field per mission (Phase 6), but not the richer PREVIEW/TEST intermediate stages or a per-viewer simulation tool.
- §50 (Game Template Library) → new scope, a real productivity win for admins once the Challenge/Game Builder exists.
- §51 (AI-Assisted Game Master) → explicitly requires "AI never autonomously awards points or launches live events. Human remains in control" — consistent with this project's own non-negotiable that Wally/AI never becomes authoritative over game state (`docs/WALLY.md` §0.2, `CLAUDE.md`). Out of scope until the underlying Challenge/Game Builder exists to draft into.
- §52 (Difficulty Engine) → new analytics scope, depends on real completion-time/failure-rate data existing first (Phase 19 territory).
- §53 (Surprise Control) → depends on the Template Library (§50) existing first.

## What was actually adopted from this document, and when

See `docs/PROJECT_STATE.md` for the dated changelog entry.
